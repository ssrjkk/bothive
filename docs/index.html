Флот ботов.Один пульт.

BotHive запускает ботов на восьми платформах из одного дашборда: общая очередь BullMQ, движок скриптов в песочнице, вебхуки с подписью и метрики Prometheus. Весь стек поднимается через Docker Compose.

01 — Топология

Один падает — семь работают.

Каждый воркер — отдельный процесс. Нажмите SIGKILL на любом: остальные не заметят, а упавший пройдёт backoff и восстановится.

dashboard → api → redis (BullMQ) + postgres → consume → 8 воркеров
DashboardReact + antd · nginx · /api · /ws/logs
APIFastify + Prisma 7 · JWT + RBAC · /metrics
▼ enqueue · CRUD ▼
RedisBullMQ · memory · pub/sub · dedup
PostgreSQLbots · scripts · events · logs
▼ consume ▼

Из коробки compose стартует telegram, twitch, youtube, twitter. Crypto — только профилем --profile crypto. Discord, slack, bluesky — тот же образ, другой --platform: node ./dist/index.js --platform discord.

02 — Возможности

Одна инфраструктура вместо восьми ботов-снежинок.

Общий API, очередь, дашборд и движок скриптов. Каждый воркер живёт отдельным процессом и масштабируется независимо.

Один control plane

Подключение, отключение и любое действие бота — job в BullMQ. Перезапуск API или воркера не теряет управление.

queues

Восемь адаптеров

Telegram long-polling или webhook, Twitch IRC + Helix, YouTube LiveChat, Twitter v2, Discord, Slack, Bluesky. Crypto/Binance — отдельным профилем.

adapters

Песочница скриптов

Node vm: process и require недоступны, бесконечные циклы убиваются таймаутом, fetch проверяет SSRF на каждом редиректе.

script engine

Вебхуки

События уходят на ваш endpoint с HMAC-подписью X-BotHive-Signature. Приватные и loopback-адреса блокируются, доставка видна в телеметрии.

integrations

Наблюдаемость

/metrics для Prometheus, готовый Grafana-дашборд, health-score каждого бота, глубина очередей и DLQ с replay.

observability

Доступы и секреты

Токены аккаунтов — AES-256-GCM. Пароли — scrypt с pepper. Роли admin/viewer читаются из БД на каждом запросе.

security
Пул проксиHTTP/SOCKS5 на бота, ротация по приоритету, cooldown после сбоя и health-score.
Backup & restoreJSON-экспорт и импорт одной кнопкой, атомарная транзакция, шифрованные credentials.
Rate limitsБюджеты по типам действий и лимит на бота через Redis — держатся на всём флоте.
03 — Скрипты

Автоматизация без отдельного сервиса.

Скрипт прикрепляется к боту и срабатывает на событие платформы или таймер. Внутри — документированный API: сообщения, посты, реакции, HTTP-запросы и Redis-память.

  • ✓20 триггеров: message, follow, subscribe, donation, comment, interval, raid, price, trade, reaction, mention и другие.
  • ✓26 действий под платформу: sendMessage, say, tweet, post, addReaction, openModal, marketBuy, fetch.
  • ✓Redis-память: remember / recall / forget с TTL — состояние переживает рестарт воркера.
  • ✓Лимиты: maxExecutionMs 100–600 000 мс на цепочку и rateLimitPerMinute на бота.
  • ✓Проверки при сохранении: катастрофические regex, sandbox escape и запрещённые URL отклоняются API.

 Переживает сбои

          
Resilience в core, а не в каждом адаптере отдельно

          

            
Circuit breaker5 подряд ошибок подключения открывают цепь; одна проба раз в 60 секунд.

            
Adaptive backoffЭкспоненциальная задержка с джиттером, потолок — 5 минут.

            
ИдемпотентностьeventId из natural id: повторная доставка не запускает скрипт дважды.

            
DLQ + replayНеудачные jobs хранят payload и причину; replay через API.

            
Event storeКаждое событие сохраняется и воспроизводится через /api/events/:id/replay.

            
Rate budgetsУ каждого типа действий свой лимит — всплеск tweet не блокирует sendMessage.

          

        


        

          
 Закрыто по умолчанию

          
Модель безопасности из docs/security.md

          

            
CredentialsAES-256-GCM; ключи валидируются на старте, в API токены не возвращаются.

            
Паролиscrypt + pepper, логин с rate limit.

            
СессииhttpOnly cookies, короткие JWT; роль читается из БД, неизвестная — viewer.

            
RBACadmin управляет скриптами, очередями, вебхуками и бэкапами; viewer только читает.

            
SSRFВебхуки и script fetch блокируют приватные и loopback-адреса, включая редиректы.

            
ЗаголовкиHSTS и security headers на каждом ответе API и дашборда.
