# Деплой на Waifly (бесплатно, €0, без карты)

Waifly — французский хостинг, бесплатный тариф: **300 МБ RAM, 1 ГБ диска, 30% CPU, без карты**.
Это единственный вариант без карты, у которого есть настоящий диск, а SQLite-файл
именно диск и требует.

## Что уже сделано за тебя

Замер на реально работающем сервере: **37 МБ RAM** при лимите 300 МБ. Запуск укладывается
с восьмикратным запасом. Единственное узкое место — сборка, и поэтому мы не собираем
на сервере, а заливаем готовым.

## Шаги

### 1. Создай сервер

В `dash.waifly.com` → **Servers** → Create:

- **Egg**: NodeJS
- **Region**: FR2 (FR1 бывает полным)
- **Name**: ezoffer

### 2. Собери пакет у себя на компьютере

```bash
npm run build
node scripts/package-deploy.mjs
```

Получишь папку `deploy-out` (~50 МБ). Убедись, что в ней **нет** каталога `data` —
скрипт проверяет это и падает, если база туда попала.

### 3. Залей файлы

Через файловый менеджер `panel.waifly.com` или SFTP. В корень сервера положи
**содержимое** `deploy-out` (то есть `.next/`, `public/`, `scripts/`, `.env`,
`deploy/` — не саму папку `deploy-out`).

### 4. Пересобери better-sqlite3 под Linux

**Это обязательный шаг, его нельзя пропустить.** Модуль нативный и собран под
Windows на твоей машине — на сервере он не запустится.

В консоли панели:

```bash
cd ~/ezoffer
apt-get update -qq && apt-get install -y python3 make g++
npm install better-sqlite3 --build-from-source
```

Если `apt-get` недоступен в контейнере, напиши — подберём путь. Без этого шага
сервер стартует и сразу падает с ошибкой про нативный модуль.

### 5. Пропиши `.env`

```bash
nano .env
```

Обязательно:

```
SITE_URL=https://<твой-адрес-из-панели>
PORT=3000
EZOFFER_DB_PATH=./data/ezoffer.db
PAYMENT_HMAC_SECRET=<случайная строка 32+ символа>
OAUTH_STATE_SECRET=<другая случайная строка>
```

`SITE_URL` участвует в OAuth redirect_uri, в письмах и в sitemap. Пропишешь неверно —
вход через GitHub вернёт ошибку, а письма будут со ссылками на чужой домен.

Случайную строку можно получить так:

```bash
openssl rand -hex 32
```

### 6. Запусти

В панели → **Startup** (или Console):

```bash
node scripts/start-hosting.mjs
```

Именно этот скрипт, а не `start-prod.mjs`: первый — для плоского пакета
хостинга, второй — для локального запуска из репозитория.

**Про порт.** Панель не даёт приложению порт 3000: контейнеру назначают
свободный порт хоста и передают его в `SERVER_PORT`. Скрипт сначала берёт
`PORT` из `.env`, потом `SERVER_PORT`, и только потом 3000. Если в `.env`
прописать `PORT=3000`, а панель выдала другой порт, сайт не откроется при
вполне работающем приложении. **Поэтому в `.env` порт не указывай** — оставь
его пустым, пусть решает панель.

Проверка, что всё поднялось:

```bash
curl http://localhost:3000/api/health
```

Если знаешь назначенный порт (видно в панели), подставь его вместо 3000.
Ожидается `{"status":"ok","db":"up","uptime":N}`.

## Адрес

Бесплатный тариф Waifly не даёт ни поддомен с SSL, ни нормальный домен — будет
адрес вида `xxxx.waifly.gg:3000`. Работать будет, выглядит неважно.

Свой домен подключается в панели через A-запись на `5.180.34.45`, TLS выпускается
автоматически. Домен покупается отдельно, с российскими картами — только на
зарубежном регистраторе.

## Важно знать заранее

**Планировщик откликов живёт внутри процесса.** Пока контейнер запущен, автоотклики
тикают. Остановишь — остановятся. В Waifly нет планировщика вроде systemd, так что
автозапуск после перезагрузки зависит от настроек панели.

**Антиабуз:** сервер, который не работал 3 дня, приостанавливается. Пока приложение
принимает запросы — этого не случится.

**Бесплатный тариф запрещает VPN, прокси и туннели** — Cloudflare Tunnel здесь
не заведётся.

**CPU ограничен 30%** — каталог вакансий обновляется медленнее, чем на своём сервере.
На работу кабинета это не влияет.

## Бэкапы

`node scripts/backup.mjs` — согласованный снимок SQLite с проверкой целостности
и сверкой числа строк. Запускай по расписанию (в панели есть Scheduled Tasks):

```bash
cd ~/ezoffer && node /home/container/ezoffer/scripts/backup.mjs
```

Копия одного файла `ezoffer.db` при работающем сервере **не годится**: база живёт
в режиме WAL, и свежие изменения лежат в `ezoffer.db-wal`. Скрипт использует
`.backup()`, поэтому сервер останавливать не нужно.
